**A Patch Is Not Proof**

  Tests Pass?

        |

 Security Assumed

**Passing a test does not prove that a vulnerability has been eliminated.**

## SLIDE 3 — WHY EXISTING APPROACHES FALL SHORT



Title:



**Verification Has a Trust Problem**



Compare traditional approaches:



| Approach | Limitation |

|---|---|

| Static analysis | Identifies patterns but may not prove runtime behavior |

| Unit tests | Usually test known scenarios |

| ML classifier | Predicts risk, does not prove exploitability |

| Patch generator | Can produce incomplete fixes |

| Fixed payload lists | May miss unfamiliar query structures |

| Self-verification | Risks trusting the same assumptions that produced the patch |



Make the key point:



**The system that creates a patch should not be the only system that approves it.**



Use a clean visual comparison rather than a dense table if it improves the slide.
